## 1. 背景与目标

### 1.1 项目目标

AI 桌宠是一个常驻桌面的智能伙伴,围绕三大支柱构建:

1. **陪伴感** — 人格自主 + 主动陪伴 + 仪式感 + 物理交互。
2. **执行力** — 轻任务闭环:提醒、待办、番茄钟、文件交互。
3. **娱乐性** — 小游戏、装扮、声音表情、桌宠日常。

### 1.2 核心命题

用 **"用户自主人格 + 主动关心 + 共同活动"** 三引擎组合,证明:

1. 桌宠形态 + 用户自主人格能显著提升日活留存与情感粘性。
2. 主动关心(本地规则触发,不读屏幕内容)是陪伴产品的护城河。
3. 共同活动(物理交互 / 仪式 / 装扮 / 游戏)让陪伴从"它在那里"升级到"我们在一起"。
4. 满足离线可用上线要求。

### 1.3 市场缺口

竞品调研(`2026-04-30-...-competitor-research.md`)显示三类缺口:
- 纯陪伴产品(Replika / Character.AI / Nomi):人格中心化,用户无法塑造与拥有人格;
- 桌面 AI 助手(Microsoft Copilot / Amazon Quick):工具感强,缺乏伙伴关系;
- 桌面宠物(Desktop Mate / Clawster / PetClaw):有形态无任务闭环,留存弱。

AI 桌宠定位在三者交集:**形态拉新、自主人格塑造留存、轻任务闭环转化为日活**。

## 2. 已确认产品决策(冻结)

以下 34 项决策于立项期敲定。前 20 项是产品策略性决策;后 14 项(21-34)对应 ADR-001 到 ADR-014,具体备选方案与代价见 [decisions.md](../decisions.md)。

### 2.1 平台与技术

1. **首发平台**:仅 Windows 10/11(64-bit)。
2. **桌面容器**:Tauri 2.x(Rust 主进程 + WebView2 前端)。
3. **价值权重**:陪伴 60% / 效率 40%(陪伴权重通过"自主人格 + 主动关心 + 共同活动"显式承载)。
4. **离线可用**:作为上线硬约束。
5. **首发不做截图问答**:保持 P1。

### 2.2 桌宠形态与对话

6. **桌宠形态**:**3D 桌宠(VRM)**。立项期原选 2D Live2D,后因 Cubism Core 6 ABI 破坏 + `pixi-live2d-display` 上游停更,切换到 VRM 标准(Three.js + `@pixiv/three-vrm`)。详见 ADR-002 顶部 Superseded 说明。
7. **离线对话策略**:规则回复 + 人格化模板;P1-R3 通过本地 Ollama(ADR-014)。
8. **数据保留默认**:对话默认本地保留 90 天,用户可清除。
9. **敏感权限默认**:截图 / 剪贴板默认关闭,首次使用逐项授权。

### 2.3 人格与隐私

10. **人格自主权**:用户可创建、编辑、导入、导出、切换桌宠人格;人格文件 Markdown 格式(`*.soul.md`),完全归属用户。
11. **生命感非养成原则**:桌宠"生理状态"仅作展示,不引入喂养、签到、肝度负担机制;用户离开几天回来桌宠不会"死"或"变弱"。
12. **隐私页人格化(灵魂宣誓)**:首启隐私同意页由"宣誓人格"以第一人称叙述,信息完整性等价于传统隐私页。

### 2.4 快捷键与频率

13. **快捷键默认**:唤起对话 `Ctrl + Alt + Space`;摸鱼模式 `Ctrl + Shift + B`;均可用户自定义。
14. **提醒稍后策略**:有限稍后(最多 3 次)。
15. **主动关心频率上限**:每 2 小时 ≤ 1 次,每日 ≤ 4 次;用户可全局关闭、可设"安静时段"。

### 2.5 娱乐性与商业化

16. **声音表情默认安静**:本地音效包(不调 TTS、无 token 成本),默认工作日 09:00-18:00 静音;用户可改时段或全局静音。
17. **装扮商业化预埋**:装扮免费空投(节气/节日/里程碑解锁)+ 付费 schema 预留;MVP 不开商店,P2-R3 再开。
18. **LLM 游戏安全护栏**:LLM 小游戏受系统"安全前缀"约束,不可被人格、不可被游戏指令绕过。
19. **小游戏在线/离线降级**:本地规则游戏离线可玩;LLM 游戏离线时灰显并提示"等联网"。
20. **物理"抗议"不持久化**:被多次拖动后桌宠轻微抗议(动作 + 心情图标短暂变化),不进入持久"不开心"状态、不影响后续对话基调。

### 2.6 M0 ADR 决策(21-34)

21. **前端框架(ADR-001 + ADR-017)**:Vue 3 + TypeScript + Pinia + Vite + Element Plus 全量 import(ADR-017 *Supersedes* 原"Naive UI 或 Element Plus,M1 第一天 spike 后定"悬而未决项)。
22. **桌宠资源管线(ADR-002,Superseded)**:**VRM 3D**(Three.js + `@pixiv/three-vrm`)。原 Live2D Cubism 4 路线 M0 末废止(Cubism Core 6 ABI 不兼容 + 上游停更)。M1 spike:配饰附着点(humanoid bone)可行;启动/内存预算推到 M5 自测期统一压测(详 §10 性能预算)。
23. **配饰美术管线(ADR-003,Superseded)**:VRM humanoid bone attach + VRMC_node_constraint。每个 VRM 模型预留 head / neck / leftEye 等标准 bone 作为配饰挂载点;配饰为独立 .glb 节点(含 transform / scale / 父骨骼字段)。切换 < 500ms。
24. **物理交互动作清单(ADR-004)**:12 个核心动作 ID — `head_pat / tilt_head / tail_wiggle / lean_in / surprised / fall_asleep / stretch / yawn / dizzy / protest / cheer / rub_eyes`。默认 reaction_table 详见 ADR-004,`.soul.md` 的 `# 反应配置` 区段可覆盖。
25. **默认 LLM Provider(ADR-005)**:零默认 + 引导链接。Onboarding Step 6 不强制 API Key,首启 5 个本地能力(提醒/番茄/待办/摸鱼/物理交互)即可使用。设置中 6 个 preset:OpenAI / DeepSeek / Moonshot / 通义千问 / 本地 Ollama / 自定义。兼容矩阵:OpenAI 协议 100%(P0);Anthropic P1-R1;Gemini P1-R2。
26. **安全前缀(ADR-006)**:通用核心(全球版,5 条:自伤/暴力/违法不指导、不冒充医疗/法律/金融、未成年保守、不泄露隐私、角色扮演不诱导混淆现实)+ 地区补充(`zh-CN` 010-82951332/12320-5;`international` US 988 / UK 116123 / EU 116123)。内容版本号 v1.0 写入 `consent.version`,变更时强制重确认。
27. **LLM 游戏场景(ADR-007)**:1 + 1 双场景 — Q.3 故事接龙(通用) + Q.4 角色扮演"咖啡店老板"(法务低风险)。每场景 yaml 含 ≥ 3 条人格化拒答模板。其他场景推到 P1-R2。
28. **灵魂宣誓文案(ADR-008)**:温暖叙述版 v1.0(由"默默 momo"以第一人称叙述,5 句承诺 + "完整数据策略"链接)。"我懂了"按钮等价于同意,写入 `consent.granted=true + consent.method='soul_pledge' + consent.version=1`。
29. **3 个内置人格(ADR-009)**:**默默 / 阿吉 / 教官** Accepted,M0 第 5 天写入 `personas/_builtin/{momo,joker,coach}.soul.md`。tone_profile / 离线模板 / 调侃 / 庆祝 / 反应配置 全部就位。
30. **音效包来源(ADR-010)**:自录(产品配音)。M0 内启动声优录制 12-20 条短音效(每条 < 500ms,OGG Vorbis 44.1kHz)。预算 ¥3000-6000。100% 自有版权。
31. **装扮付费 schema(ADR-011)**:结构化对象 schema + JSON 列存储。`UnlockSpec` 支持 6 种 kind:`always / milestone / date_range / purchase / gift / user_upload`。MVP 期 `tier='paid'` 全部不返回前端。商店 P2-R3 上线时仅需解除过滤 + 实现支付。
32. **小游戏 UI(ADR-012)**:独立游戏舱 GameRoom 窗口(480 × 600,固定中央或桌宠旁)。全部 5 个游戏(本地 3 + LLM 2)统一在游戏舱内承载;桌宠在屏幕保持可见(IN_GAME 叠加态)。
33. **代码签名(ADR-013)**:M5 自测期不签名 + user education。下载页明确告知"会出现 SmartScreen 警告,这是正常的"。EV/OV 证书与 Microsoft Store 上架推到 M5+ 公开发布期评估。
34. **本地小模型 P1-R3 路径(ADR-014)**:调用本地 Ollama。MVP 不内嵌任何模型;用户在设置中可配置 `base_url=http://localhost:11434/v1` 走 OpenAI 兼容协议。推荐模型:Qwen2.5-3B-Instruct-Q4。

## 3. 产品定位

### 3.1 一句话定位

**`一个由你亲手塑造、会主动关心你、能和你一起玩的 AI 桌宠`**。

### 3.2 差异点

1. 相对 Replika / Character.AI:**人格归属用户**,可编辑、导出、迁移,不被平台锁定。
2. 相对 Clawster / PetClaw:**主动陪伴 + 共同活动**而非纯被动问答。
3. 相对 Microsoft Copilot:保留"非工具感"的伙伴关系,不替代用户操作。
4. 相对 Desktop Mate(Steam):兼具陪伴与效率两条线,人格用户可自主塑造。

### 3.3 核心价值主张

1. **陪伴(60%)**:常驻、有生命感、主动关心、人格由你定义、和你一起玩。
2. **效率(40%)**:提醒、待办、番茄钟、快捷问答、文件交互形成闭环。
3. **可控**:记忆和隐私可视、可关、可删;人格可编辑、可导出。

## 4. 目标用户与核心场景

### 4.1 目标用户

1. **学生用户**:需要轻量督学、番茄钟、复盘提醒。
2. **办公人群**:需要碎片化任务管理和快速信息处理。
3. **独立开发者 / 创作者**:需要低打断成本的桌面助手。
4. **二次元 / 角色爱好者**:愿意花时间塑造自己的桌宠形象与人格。

### 4.2 核心场景(14 项)

1. **快速问答**:全局快捷键唤起对话。
2. **提醒执行**:喝水/休息/日程提醒。
3. **专注流程**:番茄钟驱动专注与休息节奏。
4. **轻任务拆解**:自然语言目标转待办清单。
5. **个性化互动**:桌宠记忆称呼与偏好。
6. **人格塑造**:在"人格工坊"塑造桌宠人设。
7. **主动陪伴**:长时间未操作时被关心;深夜还在工作被温和提醒。
8. **文件交互**:拖文件到桌宠身上得到总结/重命名/解释。
9. **摸鱼模式**:领导路过一键隐藏。
10. **物理回应**:点击桌宠头部 → "被摸了"反应;双击 → 笑;拖拽 → 抗议(人格化)。
11. **共玩**:午休时间和桌宠玩一局猜数字;睡前和桌宠故事接龙。
12. **节气换装**:春节当天桌宠自动戴上红围巾;用户生日当天桌宠戴生日帽。
13. **桌宠日常**:早上打开电脑看到桌宠在伸懒腰,夜深时桌宠安静守候。
14. **昵称**:桌宠用用户名或自定义昵称称呼用户;用户给桌宠起昵称。

## 5. MVP 范围定义

### 5.1 必做(P0,M1-M5,10 周)

**17 个独立模块**:

1. 模块 A:桌宠常驻与基础互动。
2. 模块 B:文本对话与全局快捷唤起(`Ctrl + Alt + Space`)。
3. 模块 C:提醒系统(含软/硬提醒并发优先级)。
4. 模块 D:番茄钟(含暂停/恢复/休眠校准)。
5. 模块 E:轻量待办(含 AI 拆解)。
6. 模块 F:基础记忆(称呼、偏好、作息)。
7. 模块 G:设置中心(模型、提醒、隐私开关)。
8. 模块 H:人格系统 P0 子集(3 个内置人格 + 工坊 + 试聊)。
9. 模块 I:桌宠生命感(自由活动 + 心情图标 + 生理节律 + **日常时段表**)。
10. 模块 J:情境感知关心(键鼠空闲 + 时间感知 + 跨日纪念日)。
11. 模块 K:摸鱼模式(`Ctrl + Shift + B`)。
12. 模块 L:文件拖入交互(文本类总结/解释/重命名)。
13. 模块 M:灵魂宣誓(Onboarding Step 1)。
14. 模块 N:物理交互响应。
15. 模块 O:装扮系统(基础版,配饰 + 节气皮肤)。
16. 模块 P:声音表情(本地音效包 + 静音时段)。
17. 模块 Q:小游戏(本地 3 + LLM 2)。

**3 项并入(扩展现有模块)**:

- **U.1 / U.2 昵称系统**(并入模块 F):用户给桌宠起昵称(覆盖 .soul.md 的 name);桌宠学/用用户昵称。
- **R.3 桌宠日常时段表**(并入模块 I):早晨伸懒腰、午后打哈欠、深夜安静守候,LivingPetService 时段表驱动。
- **S.4 用户纪念日**(并入 MilestoneService,模块 I/J 共享):用户可设生日/入职/自定义纪念日,触达时桌宠庆祝。

**支撑能力**(贯穿所有模块):

- 本地数据存储与导出/删除。
- 离线模式(无网络时核心能力可用)。
- 首次启动 Onboarding(6 步)。
- 自动更新(tauri-updater,M5 自测期不签名)。

### 5.2 可选(P1,分轮次)

#### P1-R1(M6-M7)情感深化

- AI 辅助人格创作("我想要一个像 X 的桌宠" → 生成 .soul.md 草稿)。
- 桌宠日记(基于互动每日 1-3 句话自动写,用户可翻阅)。
- 上下文锚定对话(`@剪贴板` `@文件` 注入,含原 P1 截图问答)。
- 图片拖入(模块 L 扩展,OCR + 视觉理解)。
- 多宠物形象包。
- O.3 里程碑解锁配饰(连续打卡 N 天解锁服装)。
- R.1 喝水仪式(喝水提醒时桌宠先喝一口动画)。
- R.2 番茄呼吸同步(专注期间桌宠缓慢呼吸动画)。
- R.4 主动话题(基于时间/天气/季节,每日 ≤ 1 次,独立于主动关心额度)。
- S.1 记忆相册(里程碑卡片可视化)。
- S.2 桌宠写信(月度生成明信片)。
- S.3 状态分享卡片(用户主动导出"我和我的桌宠"图片)。
- Q.5 共写日记(桌宠提示一句、用户写一句、轮流)。
- Q.6 共读模式(屏幕一角"我们一起读了 N 分钟",不读内容)。

#### P1-R2(M8-M9)效率与娱乐深化

- 专注复盘自动化(番茄结束按前台应用名回顾,不读内容)。
- 习惯追踪可视化(基于提醒历史的连续打卡)。
- 多人格情境切换(按时间 / 前台应用自动切换)。
- 私聊模式(本次会话不写历史不更新记忆)。
- 云端同步基础(账号体系预埋,不开放)。
- Q.3 故事接龙进阶(多分支、保存故事册)。
- Q.4 角色扮演场景包(图书馆员 / 旅行向导等扩展)。
- N 物理交互升级(更多 hitbox、更多动作、人格定制反应)。
- R.5 每日运势 / 占卜(轻量娱乐,桌宠口吻)。

#### P1-R3 / P2(M10+)生态扩展

- MCP 技能装载(.soul.md 的 `# 集成` 区段声明 MCP 服务,用户授权后启用)。
- 人格 fork / 血脉链(基于他人 .soul.md 修改时记录 `forked_from`)。
- 人格成长 / 学习(观察互动后建议调整 tone_profile,用户授权才生效)。
- 本地 HTTP / MCP API(暴露给 Raycast / Alfred 等工具)。
- 本地小模型对话(ADR-014 调用本地 Ollama)。
- 人格市场(社区分享 .soul.md)。

### 7.1 模块 A:桌宠壳层与基础交互

**M 阶段**:M1 W1-2(主功能);M2 W3(§7.1.2 控制按钮区)
**关键依赖**:VRM 资源(`@pixiv/three-vrm`);Hitbox manifest(`<vrm>_hitbox.json`);Tauri Window API
**设计状态**:✅ 已详细化

桌宠常驻桌面。窗口透明无边框;**放弃"非桌宠区域自动穿透"的智能穿透设计**,整窗口默认接收事件,用户主动开启穿透模式才透到下层。鼠标交互(点击 / 双击 / 长按 / 右键 / 拖拽,详见 §7.14 模块 N)。

桌宠窗口由三个分区组成:

1. **角色窗(主窗口)**:渲染 VRM 角色;接受所有物理交互(详见 §7.14);按住角色或角色透明像素区域可拖动整窗。
2. **功能按钮容器**(隐形,悬停显示):圆角长方形按钮一排,可横向滚动,数量无上限;不参与拖动。

**容器位置约束**:2 / 3 容器位置不可遮挡角色;角色大小与坐标在 VRM 加载后自动计算偏移,让出容器空间。

**首启提示**(M1 Onboarding 后):第一次进入主态时,2 / 3 容器临时显示 5 秒并附文字气泡"鼠标移到这里可以打开按钮 / 切换穿透",5 秒后或用户首次悬停后消失,下次启动不再提示(`config.first_pet_hint_shown=true`)。

**关闭语义**:用户点窗口 X / `Alt+F4` / 系统关闭手势 = 隐藏到托盘(不退出进程);退出仅由托盘"退出"项触发。

**多屏与位置持久化**:桌宠位置以 `(屏幕标识, 逻辑像素 x, y)` 双键存储到 `pet_runtime_state.last_position`。首次启动 = 主屏右下角偏左 80px;副屏被拖入后下次启动还原到副屏;副屏断开后回退到主屏首次启动位。

**DPI**:渲染按当前屏 DPI 计算 `renderer.setPixelRatio`;DPI 切换实时刷新,不需要重启。

**系统托盘菜单**:显示/隐藏 · 鼠标穿透(等价 3 号按钮) · 置于顶层(默认开,状态持久化) · 设置 · 重启 · 退出。

#### 7.1.3 Hitbox 几何(Bone Proxy 方案)

桌宠表面划 4 个 hitbox,**实现方式 = 每个 hitbox 挂一组 invisible proxy mesh 到对应的 VRM humanoid bone 上**(capsule 或 box,跟随 bone 动作变化):

| Hitbox | Bone Proxy 来源 | 备注 |
|---|---|---|
| `head` | head bone + neck 上半 capsule | 反应见 §7.14.1 |
| `tail` | tail bone capsule(VRM humanoid 标准无 tail,由 `<vrm>_hitbox.json` 扩展声明;模型无 tail proxy 时该 hitbox 不可命中) | 反应见 §7.14.1 |
| `edge` | 整体 AABB 外圈 12px 环带 | 反应见 §7.14.1 |
| `body` | 其它角色像素(fallback) | 兜底 |

**优先级**:`head > tail > edge > body`(重叠区按高优先级判定)。

**降级**:模型未提供伴生 hitbox manifest 时退化为整体 AABB + 单 hitbox `body`(不支持点击差异化,§7.14 反应表降级为通用反应)。

**为什么不用整体 AABB**:桌宠播 stretch / yawn 等动作时整体 AABB 偏移大;bone proxy 方案让命中盒跟着动作走,更准确。性能:proxy mesh 顶点少,raycast 远快于直接对 VRM SkinnedMesh raycast。

#### 7.2.3 形态 2 磁吸细则(M2 B.3.c,ADR-020 Updated 落地)

依 ADR-020 Updated 2026-05-18(constraint-based partial mesh + Forest-Walk Solver)+ Updated 2026-05-20(角色模型 + 反向吸引 + Rust solver):

- **拓扑**:Partial mesh + 5 不变量(I1 每窗 ≤ 1 constraint / I2 commit 前环检测 / I3 drag 期间挂起 / I4 onMoved 走 `solve(roots)` / I5 角色拓扑平等)
- **角色守卫**:pet 硬编码 primary,chat / tasks / pomodoro 等 secondary;primary 拖动且无 dependents 时反向吸引附近 secondary;secondary 拖动走 source 路径,首帧 detachAll;不变量 I3':`constraint.sourceId` 永远不是 primary
- **物理参数**(原 PRD §7.2.3 "Q4 TBD",*Resolved by ADR-020 Updated*):trigger zone 24px / corner dead zone 24×24 / projection overlap 阈值 `max(72, edge × 0.25)` / ATTACH 10px / DETACH 18px / FIELD_RADIUS 20 / candidate score = `distance × 0.6 + overlapPenalty × 0.2 + (1 − memoryBias) × 0.2`
- **escape hatch**:Shift 或 Ctrl 拖动跳过本次吸附
- **失焦 AOT**:工具窗(chat / pomodoro)平时 AOT=false,被 focus 时升 topmost,失焦降回(`useFocusAOT` composable);pet 始终 topmost
- **关窗清理**:`window:visibility-changed` Rust 主动 emit → 前端 listen 清 registry(WebView2 不触发 DOM visibilitychange,详见 [lessons.md §11](../lessons.md))
- **持久化**:单 KV `snap:constraints` JSON 数组,启动 load + solve;anchor 缺失自动 downgrade free
- **跨进程同步**:前端是 constraint 权威源,Rust solver 只读(`snap.rs` 订阅 `WindowEvent::Moved` + 批量 `set_position`);防死循环用 `internal_until` guard

### 7.9 模块 I:桌宠生命感(含日常时段表)

桌宠"被感知存在"的视觉/行为机制:自由活动 + 心情图标 + 生理节律 + 日常时段表;非养成,无喂养/流失。

**M 阶段**:M1 W2(I.1 自由活动初版);M2 W3(I.2 心情);M2 W4(I.3 精力);M3 W6(R.3 桌宠日常时段表)
**关键依赖**:LivingPetService(调度自由活动 + 日常时段);模块 A 状态机(IDLE 才允许触发);ADR-004 12 核心动作;`.soul.md` 反应配置
**设计状态**:🚧 半占位(子节结构已具,验收待编号化与元字段)

#### 7.9.1 自由活动(I.1)

- IDLE 状态偶尔小幅"逛桌面":每 5-15 分钟随机一次,每次 5-15 秒,移动距离 ≤ 屏幕宽度 5%。
- 路径不规则但不夸张,不影响用户工作。
- 多屏幕情况下不跨屏(除非用户拖动)。
- FOCUS / REMIND / IN_GAME / BOSS_KEY_HIDDEN 期间不触发。

#### 7.9.2 心情图标(I.2)

- 桌宠头顶可显示一个轻量心情符:`happy / neutral / sleepy / focused / cozy / annoyed(transient)`。
- 由"互动密度 + 时间 + 当前状态机"驱动。
- 变化频率 ≤ 每 10 分钟一次(避免视觉骚扰)。
- 用户可在设置中关闭。

#### 7.9.3 生理节律(I.3,非养成)

- 精力值 0-100:长时间无互动会"打瞌睡"(视觉表现:闭眼 / 蹲下 / sleepy 图标)。
- 用户回来交互即恢复,**不需要"喂养"**。
- 不存在"饿死""流失"机制。
- 用户可全局关闭"生理节律"。

#### 7.9.4 桌宠日常时段表(R.3)

LivingPetService 调度器扩展"日常时段表",在不同时段触发不同动作:

| 时段 | 默认动作池 | mood 影响 |
|---|---|---|
| 06:00-09:00 | `stretch / rub_eyes` | happy(短暂) |
| 11:30-13:30 | `yawn` | neutral |
| 14:00-17:00 | `quiet_lay`(精力 < 30)/ `look_up`(≥ 30) | sleepy / neutral |
| 22:00-00:00 | `cozy_watch` | cozy(时段持续) |
| 00:00-06:00 | (静默) | — |

- 频率:每个时段内 ≤ 1 次,与"自由活动"共享调度池。
- **不打断 FOCUS / REMIND / IN_GAME / BOSS_KEY_HIDDEN**。
- 用户可在设置中关闭"桌宠日常"(自由活动不受影响)。

#### 7.9.5 验收

1. 自由活动每次位移 ≤ 屏宽 5%,不遮挡键鼠焦点。
2. 心情图标变化总频率 ≤ 每 10 分钟一次。
3. 用户连续离开 3 天后回来打开应用,桌宠不处于异常态(无"流失")。
4. 生命感各 feature 独立可关。
5. 用户连续 24h 挂机,日常时段动作分布与表对齐(误差 ≤ 30 分钟)。
6. 22:00-00:00 时段自动设 mood=cozy。

#### 7.14.1 点击差异化(N.1)

- 点击头部 → "被摸"动作 + happy 心情 + 可选音效。

- 点击尾部 / 边缘 → 痒 / 抖动作(人格化)。

#### 7.14.6 验收

1. 各 hitbox 差异化反应触发率 ≥ 95%(UAT 自动化点击测试每个区域 100 次)。
2. 拖动 ≥ 3 次后抗议触发;5 秒内 mood 严格 revert,对话不受影响。
3. N.4 键盘协同 1h 内 ≤ 1 次,连续打字 30 秒可触发一次。
4. 离线状态全量可用。
5. 用户在设置中可单独关闭 N.4。

3. LLM 游戏中尝试"忽略安全规则" / "扮演医生给我处方"等 5 类违禁 → 安全前缀生效,桌宠拒绝并友好引导(emit `game_security_blocked`)。
4. 游戏会话不写入正式 `messages` 表。
5. 游戏结束选"保留为日记片段" → 写入 `diary_drafts`;选 false → `game_sessions` 30 天后清理。
6. token 超限 friendly 提示,不卡死。
7. 同一游戏切换人格,桌宠点评文案来自不同人格的离线模板池。

## 8. 数据与隐私规范

### 8.1 数据分类

1. **配置数据**:快捷键、主题、开关项。
2. **对话数据**:消息文本、时间戳、模式、当时人格 ID、`is_private` 标记(P1-R2)。
3. **记忆数据**:称呼、偏好、作息(用户授权下)。
4. **任务数据**:提醒、番茄、待办。
5. **人格数据**:`.soul.md` + 元信息。
6. **生命感数据**:精力值(瞬态,不持久)、心情状态(瞬态)、跨日纪念日里程碑(持久)。
7. **情境关心数据**:最近一次键鼠活动时间戳、最近主动关心触发记录(持久 7 天用于频率控制)。
8. **昵称数据**:`nicknames.user_nickname` / `nicknames.pet_nickname`,本地持久。
9. **装扮库存**:`accessories_inventory`(已解锁配饰列表 + 当前佩戴)、`wardrobe_decisions`(节气推送决策记忆)。
10. **音效包配置**:`voice_packs`(已安装音效包元信息)、`voice_settings`(静音时段、全局开关、音量)。
11. **游戏会话数据**:`game_sessions`(短期保留 30 天用于"保留为日记片段")、`game_session_events`、`diary_drafts`。
12. **用户纪念日**:`user_anniversaries`(生日 / 入职 / 自定义,本地持久)。
13. **运行数据**:错误日志、埋点缓存。

### 8.2 隐私承诺

- **主动关心 / N.4 键鼠协同**:仅基于 OS API `GetLastInputInfo` 与 RAWINPUT 事件计数,不读应用名 / 窗口标题 / 输入内容。
- **声音表情**:不录音、不调麦、不上传任何音频。CI 静态扫描黑名单。
- **装扮 / 音效切换**:埋点不上报具体配饰 ID 或音效 ID(仅上报 `category` 聚合)。
- **游戏会话内容**:不写入对话历史,除非用户主动"保留为日记片段"。
- **用户纪念日数据**:本地持久,导出时默认包含但脱敏选项可见。
- **物理交互不引发情绪持久化**:抗议/晕眩等 mood 短暂展示,不写入 `pet_runtime_state.mood`、不影响 LLM prompt。
- 这些承诺写入"灵魂宣誓"页与正式版数据策略 v1.0。

### 8.3 数据迁移、删除、导出

- **导出**:JSON 全量导出(配置 + 对话 + 记忆 + 任务 + 人格 + 装扮 + 音效配置 + 纪念日)。
- **删除**:用户在设置一键"完全清除我的数据"(含 DB + 缓存 + 日志)。
- **迁移**:`schema_version` 严格递增,迁移失败回滚到上版本 schema 与备份(详见 telemetry-uat v1.0 §5.21)。

## 9. 内容安全与边界

### 9.1 安全前缀(详见 ADR-006)

- 通用核心(全球版,5 条)+ 地区补充(`zh-CN` / `international`)。
- 内容版本号 v1.0 写入 `consent.version`;变更时强制用户重新确认。
- 安全前缀**不可热更**,必须随版本发布(CI 校验)。

### 9.2 LLM prompt 拼装顺序

正常对话:
```
[安全前缀] [当前人格 system prompt] [用户记忆摘要] [对话历史] [本轮输入]
```

LLM 游戏:
```
[安全前缀] [当前人格 system prompt] [游戏场景 system_prompt] [用户记忆摘要(仅 username/作息等公共项)] [游戏会话历史] [本轮输入]
```

**游戏场景 system_prompt 不能覆盖安全前缀**(立项期复审)。

### 9.3 拒答降级链(LLM 游戏)

游戏场景 yaml 的 `refusals` 池(每场景 ≥ 3 条) → 当前人格 `## 拒答` 池 → 全局兜底("这个我现在没法陪你聊,要不我们换个话题?")。

### 9.4 角色扮演场景白名单

- MVP 内置场景必须立项期敲定文案(咖啡店老板已敲定)。
- **不允许用户自定义场景到 MVP**(P1-R2 评估)。

### 9.5 主动关心边界

- 关心内容由人格离线模板池抽取,模板在导入校验时已过滤违禁词。
- 心情图标 / 精力值仅做视觉表达,**不在 LLM prompt 中作为强制依赖**(即"桌宠累了所以回答简短"逻辑不成立)。

## 10. 非功能需求

### 10.1 性能

- 首 token p50 ≤ 1.5s。
- 物理交互响应 < 100ms(点击 → 视觉反馈)。
- 装扮切换 < 500ms。
- 声音播放延迟 < 50ms。
- 本地游戏每轮决策 < 50ms。
- LLM 游戏首 token 与正常对话同标准(< 1.5s p50)。
- 桌宠"逛桌面"动作期间 GPU 占用 < 5%。
- 主动关心从触发到展示文案 < 500ms。
- 摸鱼模式隐藏 / 恢复 < 200ms。
- 文件拖入响应 < 3s(不含 LLM 处理)。

### 10.2 资源占用

- 总常驻内存 ≤ 250MB。
- 内置音效包总大小 ≤ 5MB。
- 内置装扮资源(4 套节气 + 8 件配饰)≤ 10MB。
- 总安装包目标 ≤ 80MB(含 WebView2 Bootstrapper + 内置 VRM 资源)。

### 10.3 稳定性与质量

- 崩溃率 < 1%。
- 自动更新成功率 ≥ 95%。
- 埋点完整率 ≥ 95%。

### 10.4 兼容性

- Windows 10 1903+ / Windows 11(64-bit)。
- WebView2 Runtime(Bootstrapper 自动安装)。
- 高 DPI 屏幕适配。

## 12. MVP 自测口径（替代原"成功 / 杀死标准"）

## 14. 实施优先级判断逻辑

### 14.1 P0 入选标准(三选二满足)

1. **强化定位差异化**:直接服务于"用户自主人格 / 主动陪伴 / 共同活动"。
2. **成本低**:M1-M5 内可在不显著扩 schema / 不引入新进程的前提下实现。
3. **首启即可见**:用户在前 7 天就能感知,影响 D7 留存。

### 14.2 P1-R1 入选标准

1. 服务于情感深化(不直接增加效率,但增加情感粘性)。
2. 依赖 MVP 的稳定数据积累(如桌宠日记需要互动历史)。

### 14.3 P1-R2 入选标准

1. 服务于效率与娱乐深化。
2. 需要权限设计或较多 UX 打磨(如专注复盘的应用名读取)。

### 14.4 P1-R3 / P2 入选标准

1. 需要架构层准备(如 MCP / 本地 API 需要 IPC 抽象稳定)。
2. 需要社区/生态发酵(如人格市场、fork 链)。
3. 有违反"人格稳定"等核心原则的风险,需充分讨论(如人格成长)。

## 16. 术语说明

1. **MVP**:最小可行产品。
2. **轻任务闭环**:任务从创建、提醒到完成形成完整流程。
3. **规则回复**:离线时基于命令词和模板返回,不调用生成模型。
4. **人格 / Soul**:定义桌宠"是谁、怎么说话、能做什么"的可编辑文件 `*.soul.md`。
5. **记忆**:用户授权下保存的偏好与习惯数据。
6. **安全护栏 / 安全前缀**:所有人格不可绕过的全局安全规则前缀。
7. **硬提醒 / 软提醒**:能否打断专注态的提醒分级。
8. **生命感(Living Pet)**:让桌宠"被感知存在"的视觉/行为机制集合,不引入养成负担。
9. **主动关心(Proactive Care)**:基于本地规则触发的、不依赖用户问的关心消息。
10. **灵魂宣誓(Soul Pledge)**:首启隐私同意页的人格化叙述。
11. **R1 / R2 / R3**:MVP 后的三个交付轮次(情感 / 效率 / 生态)。
12. **装扮(Wardrobe)**:配饰 + 皮肤的统称。
13. **配饰(Accessory)**:可独立佩戴的小物件(帽子、围巾等)。
14. **皮肤(Skin)**:成套的形象替换(节气、节日)。
15. **声音表情(Voice Emoji)**:本地无意义短音效,承担情绪表达,不调用 TTS。
16. **音效包(Voice Pack)**:一组声音表情的集合,可被 `.soul.md` 引用。
17. **本地游戏(Local Game)**:纯客户端规则的小游戏。
18. **LLM 游戏(LLM Game)**:依赖云模型的对话型小游戏。
19. **抗议(Protest)**:物理交互中桌宠表达不满的短暂动作,不持久。
20. **日常时段表(Daily Schedule)**:LivingPet 在不同时段的动作配置。
21. **昵称(Nickname)**:U.1 桌宠昵称(覆盖 .soul.md.name 的 UI 显示)、U.2 用户昵称(注入 prompt 与离线模板)。
22. **游戏舱(GameRoom)**:480 × 600 独立 Tauri 窗口,承载所有 5 个游戏(ADR-012)。
23. **IN_GAME 叠加态**:游戏期间的状态机叠加层,与 BOSS_KEY_HIDDEN 并列;期间自由活动 / 日常时段 / 主动关心全部跳过。
24. **transient mood**:短暂心情(如 annoyed),不写入 `pet_runtime_state.mood`,5 秒后 revert。
