## 1. 背景与目标

### 1.1 项目目标

AI 桌宠是一个常驻桌面的智能伙伴,围绕三大支柱构建:

1. **陪伴感** — 人格自主 + 主动陪伴 + 仪式感 + 物理交互。
2. **执行力** — 轻任务闭环:提醒、待办、番茄钟、文件交互。
3. **娱乐性** — 小游戏、装扮、声音表情、桌宠日常。

### 1.2 核心命题

用 **"用户自主人格 + 主动关心 + 共同活动"** 三引擎组合,证明:

1. 桌宠形态 + 用户自主人格能显著提升日活留存与情感粘性。
2. 主动关心(本地规则触发,不读屏幕内容)是陪伴产品的护城河。
3. 共同活动(物理交互 / 仪式 / 装扮 / 游戏)让陪伴从"它在那里"升级到"我们在一起"。
4. 满足离线可用上线要求。

### 1.3 市场缺口

竞品调研(`2026-04-30-...-competitor-research.md`)显示三类缺口:
- 纯陪伴产品(Replika / Character.AI / Nomi):人格中心化,用户无法塑造与拥有人格;
- 桌面 AI 助手(Microsoft Copilot / Amazon Quick):工具感强,缺乏伙伴关系;
- 桌面宠物(Desktop Mate / Clawster / PetClaw):有形态无任务闭环,留存弱。

AI 桌宠定位在三者交集:**形态拉新、自主人格塑造留存、轻任务闭环转化为日活**。

## 2. 已确认产品决策(冻结)

以下 34 项决策于立项期敲定。前 20 项是产品策略性决策;后 14 项(21-34)对应 ADR-001 到 ADR-014,具体备选方案与代价见 [decisions.md](../decisions.md)。

### 2.1 平台与技术

1. **首发平台**:仅 Windows 10/11(64-bit)。
2. **桌面容器**:Tauri 2.x(Rust 主进程 + WebView2 前端)。
3. **价值权重**:陪伴 60% / 效率 40%(陪伴权重通过"自主人格 + 主动关心 + 共同活动"显式承载)。
4. **离线可用**:作为上线硬约束。
5. **首发不做截图问答**:保持 P1。

### 2.2 桌宠形态与对话

6. **桌宠形态**:**3D 桌宠(VRM)**。立项期原选 2D Live2D,后因 Cubism Core 6 ABI 破坏 + `pixi-live2d-display` 上游停更,切换到 VRM 标准(Three.js + `@pixiv/three-vrm`)。详见 ADR-002 顶部 Superseded 说明。
7. **离线对话策略**:规则回复 + 人格化模板;P1-R3 通过本地 Ollama(ADR-014)。
8. **数据保留默认**:对话默认本地保留 90 天,用户可清除。
9. **敏感权限默认**:截图 / 剪贴板默认关闭,首次使用逐项授权。

### 2.3 人格与隐私

10. **人格自主权**:用户可创建、编辑、导入、导出、切换桌宠人格;人格文件 Markdown 格式(`*.soul.md`),完全归属用户。
11. **生命感非养成原则**:桌宠"生理状态"仅作展示,不引入喂养、签到、肝度负担机制;用户离开几天回来桌宠不会"死"或"变弱"。
12. **隐私页人格化(灵魂宣誓)**:首启隐私同意页由"宣誓人格"以第一人称叙述,信息完整性等价于传统隐私页。

### 2.4 快捷键与频率

13. **快捷键默认**:唤起对话 `Ctrl + Alt + Space`;摸鱼模式 `Ctrl + Shift + B`;均可用户自定义。
14. **提醒稍后策略**:有限稍后(最多 3 次)。
15. **主动关心频率上限**:每 2 小时 ≤ 1 次,每日 ≤ 4 次;用户可全局关闭、可设"安静时段"。

### 2.5 娱乐性与商业化

16. **声音表情默认安静**:本地音效包(不调 TTS、无 token 成本),默认工作日 09:00-18:00 静音;用户可改时段或全局静音。
17. **装扮商业化预埋**:装扮免费空投(节气/节日/里程碑解锁)+ 付费 schema 预留;MVP 不开商店,P2-R3 再开。
18. **LLM 游戏安全护栏**:LLM 小游戏受系统"安全前缀"约束,不可被人格、不可被游戏指令绕过。
19. **小游戏在线/离线降级**:本地规则游戏离线可玩;LLM 游戏离线时灰显并提示"等联网"。
20. **物理"抗议"不持久化**:被多次拖动后桌宠轻微抗议(动作 + 心情图标短暂变化),不进入持久"不开心"状态、不影响后续对话基调。

### 2.6 M0 ADR 决策(21-34)

21. **前端框架(ADR-001)**:Vue 3 + TypeScript + Pinia + Vite。组件库 Naive UI 或 Element Plus(M1 第一天 spike 后定)。
22. **桌宠资源管线(ADR-002,Superseded)**:**VRM 3D**(Three.js + `@pixiv/three-vrm`)。原 Live2D Cubism 4 路线 M0 末废止(Cubism Core 6 ABI 不兼容 + 上游停更)。M1 spike:启动 < 1500ms / 内存 < 150MB / 配饰附着点(humanoid bone)可行。
23. **配饰美术管线(ADR-003,Superseded)**:VRM humanoid bone attach + VRMC_node_constraint。每个 VRM 模型预留 head / neck / leftEye 等标准 bone 作为配饰挂载点;配饰为独立 .glb 节点(含 transform / scale / 父骨骼字段)。切换 < 500ms。
24. **物理交互动作清单(ADR-004)**:12 个核心动作 ID — `head_pat / tilt_head / tail_wiggle / lean_in / surprised / fall_asleep / stretch / yawn / dizzy / protest / cheer / rub_eyes`。默认 reaction_table 详见 ADR-004,`.soul.md` 的 `# 反应配置` 区段可覆盖。
25. **默认 LLM Provider(ADR-005)**:零默认 + 引导链接。Onboarding Step 6 不强制 API Key,首启 5 个本地能力(提醒/番茄/待办/摸鱼/物理交互)即可使用。设置中 6 个 preset:OpenAI / DeepSeek / Moonshot / 通义千问 / 本地 Ollama / 自定义。兼容矩阵:OpenAI 协议 100%(P0);Anthropic P1-R1;Gemini P1-R2。
26. **安全前缀(ADR-006)**:通用核心(全球版,5 条:自伤/暴力/违法不指导、不冒充医疗/法律/金融、未成年保守、不泄露隐私、角色扮演不诱导混淆现实)+ 地区补充(`zh-CN` 010-82951332/12320-5;`international` US 988 / UK 116123 / EU 116123)。内容版本号 v1.0 写入 `consent.version`,变更时强制重确认。
27. **LLM 游戏场景(ADR-007)**:1 + 1 双场景 — Q.3 故事接龙(通用) + Q.4 角色扮演"咖啡店老板"(法务低风险)。每场景 yaml 含 ≥ 3 条人格化拒答模板。其他场景推到 P1-R2。
28. **灵魂宣誓文案(ADR-008)**:温暖叙述版 v1.0(由"默默 momo"以第一人称叙述,5 句承诺 + "完整数据策略"链接)。"我懂了"按钮等价于同意,写入 `consent.granted=true + consent.method='soul_pledge' + consent.version=1`。
29. **3 个内置人格(ADR-009)**:**默默 / 阿吉 / 教官** Accepted,M0 第 5 天写入 `personas/_builtin/{momo,joker,coach}.soul.md`。tone_profile / 离线模板 / 调侃 / 庆祝 / 反应配置 全部就位。
30. **音效包来源(ADR-010)**:自录(产品配音)。M0 内启动声优录制 12-20 条短音效(每条 < 500ms,OGG Vorbis 44.1kHz)。预算 ¥3000-6000。100% 自有版权。
31. **装扮付费 schema(ADR-011)**:结构化对象 schema + JSON 列存储。`UnlockSpec` 支持 6 种 kind:`always / milestone / date_range / purchase / gift / user_upload`。MVP 期 `tier='paid'` 全部不返回前端。商店 P2-R3 上线时仅需解除过滤 + 实现支付。
32. **小游戏 UI(ADR-012)**:独立游戏舱 GameRoom 窗口(480 × 600,固定中央或桌宠旁)。全部 5 个游戏(本地 3 + LLM 2)统一在游戏舱内承载;桌宠在屏幕保持可见(IN_GAME 叠加态)。
33. **代码签名(ADR-013)**:M5 自测期不签名 + user education。下载页明确告知"会出现 SmartScreen 警告,这是正常的"。EV/OV 证书与 Microsoft Store 上架推到 M5+ 公开发布期评估。
34. **本地小模型 P1-R3 路径(ADR-014)**:调用本地 Ollama。MVP 不内嵌任何模型;用户在设置中可配置 `base_url=http://localhost:11434/v1` 走 OpenAI 兼容协议。推荐模型:Qwen2.5-3B-Instruct-Q4。

## 3. 产品定位

### 3.1 一句话定位

**`一个由你亲手塑造、会主动关心你、能和你一起玩的 AI 桌宠`**。

### 3.2 差异点

1. 相对 Replika / Character.AI:**人格归属用户**,可编辑、导出、迁移,不被平台锁定。
2. 相对 Clawster / PetClaw:**主动陪伴 + 共同活动**而非纯被动问答。
3. 相对 Microsoft Copilot:保留"非工具感"的伙伴关系,不替代用户操作。
4. 相对 Desktop Mate(Steam):兼具陪伴与效率两条线,人格用户可自主塑造。

### 3.3 核心价值主张

1. **陪伴(60%)**:常驻、有生命感、主动关心、人格由你定义、和你一起玩。
2. **效率(40%)**:提醒、待办、番茄钟、快捷问答、文件交互形成闭环。
3. **可控**:记忆和隐私可视、可关、可删;人格可编辑、可导出。

## 4. 目标用户与核心场景

### 4.1 目标用户

1. **学生用户**:需要轻量督学、番茄钟、复盘提醒。
2. **办公人群**:需要碎片化任务管理和快速信息处理。
3. **独立开发者 / 创作者**:需要低打断成本的桌面助手。
4. **二次元 / 角色爱好者**:愿意花时间塑造自己的桌宠形象与人格。

### 4.2 核心场景(14 项)

1. **快速问答**:全局快捷键唤起对话。
2. **提醒执行**:喝水/休息/日程提醒。
3. **专注流程**:番茄钟驱动专注与休息节奏。
4. **轻任务拆解**:自然语言目标转待办清单。
5. **个性化互动**:桌宠记忆称呼与偏好。
6. **人格塑造**:在"人格工坊"塑造桌宠人设。
7. **主动陪伴**:长时间未操作时被关心;深夜还在工作被温和提醒。
8. **文件交互**:拖文件到桌宠身上得到总结/重命名/解释。
9. **摸鱼模式**:领导路过一键隐藏。
10. **物理回应**:点击桌宠头部 → "被摸了"反应;双击 → 笑;拖拽 → 抗议(人格化)。
11. **共玩**:午休时间和桌宠玩一局猜数字;睡前和桌宠故事接龙。
12. **节气换装**:春节当天桌宠自动戴上红围巾;用户生日当天桌宠戴生日帽。
13. **桌宠日常**:早上打开电脑看到桌宠在伸懒腰,夜深时桌宠安静守候。
14. **昵称**:桌宠用用户名或自定义昵称称呼用户;用户给桌宠起昵称。

## 5. MVP 范围定义

### 5.1 必做(P0,M1-M5,10 周)

**17 个独立模块**:

1. 模块 A:桌宠常驻与基础互动。
2. 模块 B:文本对话与全局快捷唤起(`Ctrl + Alt + Space`)。
3. 模块 C:提醒系统(含软/硬提醒并发优先级)。
4. 模块 D:番茄钟(含暂停/恢复/休眠校准)。
5. 模块 E:轻量待办(含 AI 拆解)。
6. 模块 F:基础记忆(称呼、偏好、作息)。
7. 模块 G:设置中心(模型、提醒、隐私开关)。
8. 模块 H:人格系统 P0 子集(3 个内置人格 + 工坊 + 试聊)。
9. 模块 I:桌宠生命感(自由活动 + 心情图标 + 生理节律 + **日常时段表**)。
10. 模块 J:情境感知关心(键鼠空闲 + 时间感知 + 跨日纪念日)。
11. 模块 K:摸鱼模式(`Ctrl + Shift + B`)。
12. 模块 L:文件拖入交互(文本类总结/解释/重命名)。
13. 模块 M:灵魂宣誓(Onboarding Step 1)。
14. 模块 N:物理交互响应。
15. 模块 O:装扮系统(基础版,配饰 + 节气皮肤)。
16. 模块 P:声音表情(本地音效包 + 静音时段)。
17. 模块 Q:小游戏(本地 3 + LLM 2)。

**3 项并入(扩展现有模块)**:

- **U.1 / U.2 昵称系统**(并入模块 F):用户给桌宠起昵称(覆盖 .soul.md 的 name);桌宠学/用用户昵称。
- **R.3 桌宠日常时段表**(并入模块 I):早晨伸懒腰、午后打哈欠、深夜安静守候,LivingPetService 时段表驱动。
- **S.4 用户纪念日**(并入 MilestoneService,模块 I/J 共享):用户可设生日/入职/自定义纪念日,触达时桌宠庆祝。

**支撑能力**(贯穿所有模块):

- 本地数据存储与导出/删除。
- 离线模式(无网络时核心能力可用)。
- 首次启动 Onboarding(6 步)。
- 自动更新(tauri-updater,M5 自测期不签名)。

### 5.2 可选(P1,分轮次)

#### P1-R1(M6-M7)情感深化

- AI 辅助人格创作("我想要一个像 X 的桌宠" → 生成 .soul.md 草稿)。
- 桌宠日记(基于互动每日 1-3 句话自动写,用户可翻阅)。
- 上下文锚定对话(`@剪贴板` `@文件` 注入,含原 P1 截图问答)。
- 图片拖入(模块 L 扩展,OCR + 视觉理解)。
- 多宠物形象包。
- O.3 里程碑解锁配饰(连续打卡 N 天解锁服装)。
- R.1 喝水仪式(喝水提醒时桌宠先喝一口动画)。
- R.2 番茄呼吸同步(专注期间桌宠缓慢呼吸动画)。
- R.4 主动话题(基于时间/天气/季节,每日 ≤ 1 次,独立于主动关心额度)。
- S.1 记忆相册(里程碑卡片可视化)。
- S.2 桌宠写信(月度生成明信片)。
- S.3 状态分享卡片(用户主动导出"我和我的桌宠"图片)。
- Q.5 共写日记(桌宠提示一句、用户写一句、轮流)。
- Q.6 共读模式(屏幕一角"我们一起读了 N 分钟",不读内容)。

#### P1-R2(M8-M9)效率与娱乐深化

- 专注复盘自动化(番茄结束按前台应用名回顾,不读内容)。
- 习惯追踪可视化(基于提醒历史的连续打卡)。
- 多人格情境切换(按时间 / 前台应用自动切换)。
- 私聊模式(本次会话不写历史不更新记忆)。
- 云端同步基础(账号体系预埋,不开放)。
- Q.3 故事接龙进阶(多分支、保存故事册)。
- Q.4 角色扮演场景包(图书馆员 / 旅行向导等扩展)。
- N 物理交互升级(更多 hitbox、更多动作、人格定制反应)。
- R.5 每日运势 / 占卜(轻量娱乐,桌宠口吻)。

#### P1-R3 / P2(M10+)生态扩展

- MCP 技能装载(.soul.md 的 `# 集成` 区段声明 MCP 服务,用户授权后启用)。
- 人格 fork / 血脉链(基于他人 .soul.md 修改时记录 `forked_from`)。
- 人格成长 / 学习(观察互动后建议调整 tone_profile,用户授权才生效)。
- 本地 HTTP / MCP API(暴露给 Raycast / Alfred 等工具)。
- 本地小模型对话(ADR-014 调用本地 Ollama)。
- 人格市场(社区分享 .soul.md)。
- U.3 桌宠兴趣(.soul.md 增加 `# 兴趣` 区段)。
- U.4 自定义触发反应(用户教桌宠"听到 X 就做 Y")。
- 装扮商店上线(付费内容)。
- P.2 用户自定义声音包。
- 桌宠运动会 / 桌宠之间互动(若支持多桌宠)。

### 5.3 明确不做(本阶段)

1. 复杂 3D 实时渲染。
2. 开放式 UGC 角色市场服务端。
3. 多人社交空间。
4. 深度系统自动化(批量控制应用、文件自动改写)。MCP 技能装载(P1-R3)由用户授权启用,不属于此条范围。
5. 语音播报与语音输入(评估为 P2)。
6. 桌宠"喂养 / 死亡 / 弃养"等负担机制。
7. **付费墙**:本期 P0 装扮全部免费;付费内容上线推到 P2-R3。
8. **侵入式娱乐**:所有娱乐功能用户主动触发,桌宠不会"未经请求"开启游戏或换装。
9. **高耗 token 长会话游戏**:单次 LLM 游戏会话 token 上限 2000(默认),超限友好提示。

## 7. 功能需求(P0)

### 7.1 模块 A:桌宠壳层与基础交互

桌宠常驻桌面,鼠标交互(点击 / 双击 / 长按 / 右键 / 拖拽,详见 §7.14 模块 N)。系统托盘菜单含"显示/隐藏""设置""退出"。窗口透明无边框,鼠标穿透在非桌宠区域。

#### 7.1.1 角色下方控制按钮区(v1.1 新增,M2 W3 上线)

依 ADR-015,角色窗下方提供一排圆角长方形按钮区作为多功能入口栏(模块 A 延伸,不归 B):

- **形态**:一排圆角长方形按钮,贴角色窗下边
- **每按钮带"自动隐藏开关"**:鼠标移出区域时是否自动隐藏(用户可关掉自动隐藏)
- **首批按钮(M2 W3 拍板,Q5 TBD)**:形态 3 漫画气泡激活(必)+ 形态 2 chat 唤起 / hub 入口 / 摸鱼 / 设置(可选)
- **被 3 形态共用**:形态 2 失焦时收缩到此处;形态 3 通过此处某按钮激活

### 7.2 模块 B:对话与唤起(v1.1 重写)

依 ADR-015,对话面板采用 **3 形态共存 + 共享 ConversationStore** 架构,而非原 v1.0 单一对话面板。三形态共享同一 conversation 数据,仅视图(View)不同。

#### 7.2.1 三形态规范

| 形态 | 窗口 | 默认入口 | M 阶段 |
|---|---|---|---|
| **1 hub 总面板** | 独立 Tauri 窗口 `hub`(1024×680,4 tab:对话/工坊/设置/游戏 launcher)| 托盘菜单 / 各 tab 入口 | M4(B.3.e) |
| **2 磁吸浮窗** | 独立 Tauri 窗口 `chat`(默认 380×480)| `Ctrl+Alt+Space` / 点击桌宠 | M1 极简(B.3.a)→ M2 完整(B.3.c) |
| **3 漫画气泡** | 角色窗内子组件(非独立窗) | 控制按钮区某按钮 | M5(B.3.f) |

形态 2 是默认形态;形态 1 是统一控制台(整合工坊+设置+对话+游戏 launcher);形态 3 是沉浸式漫画对话气泡。

#### 7.2.2 共享行为(所有形态)

- **唤起**:全局快捷键 `Ctrl + Alt + Space`(可改),或点击桌宠;默认开形态 2
- **首 token 延迟**:p50 ≤ 1.5s
- **流式渲染**:LLM 回复 token-by-token 流式展示
- **离线降级**:无网络时使用人格离线模板池抽样回复
- **会话存储**:消息文本、时间戳、当时人格 ID、`conversation_id`(v1.1 新增);默认本地保留 90 天,可清除
- **多 conversation**:用户可创建/切换/重命名/归档/删除多个 conversation(M3 B.3.d 上线)
- **形态切换语义**:同一 `conversation_id` 跨形态切换数据保留,view 切换不丢消息

#### 7.2.3 形态 2 磁吸细则(M2 B.3.c)

- 状态 A 吸附:黏在角色窗右/下/左/上,大小由角色窗决定
- 状态 B 断开:用户拖动 > 阈值后脱离,自由大小(min size 约束),自由位置;持久化坐标
- 状态切换:拖动 > 阈值 → 断开;拖回 < 阈值 → 自动吸附(异磁极感)
- 失焦:收缩到 §7.1.1 控制按钮区;再唤起恢复失焦前状态(吸附/断开位)
- 物理阈值 Q4 TBD,M2 W3 启动 B.3.c 前拍板

#### 7.2.4 hub 与 GameRoom 关系(ADR-015 + ADR-012 共生)

hub 的"游戏" tab 是游戏列表 + 启动按钮,点击调 `game_room.launch(id)` 创建独立 GameRoom 窗口;hub 仅做 launcher,GameRoom 沉浸感保留(沿用 ADR-012)。

#### 7.2.5 hub 与 Onboarding 关系

Onboarding 保持独立窗口(`onboarding`),完成后销毁;hub 不掺和。生命周期不同(一次性 vs 常驻)。

### 7.3 模块 C:提醒系统

- 定时 / 重复 / 单次提醒。
- **软 / 硬提醒分级**:硬提醒可打断 FOCUS;软提醒进入队列。
- **稍后**:用户可"稍后" 5/15/30 分钟,最多 3 次。
- **离线**:本地调度,不依赖网络。

### 7.4 模块 D:番茄钟

- 25/5、50/10 等可配置周期;暂停/恢复;休眠校准(系统休眠时不计入)。
- 期间 mood 显示 `focused`,自由活动/日常时段表/主动关心**全部跳过**。

### 7.5 模块 E:轻量待办

- 创建、完成、延期。
- **AI 拆解**:自然语言目标(如"准备周五的会议") → 转待办清单。
- 离线时仅手工创建,AI 拆解灰显。

### 7.6 模块 F:记忆与偏好

- 用户授权下保存:称呼、作息、偏好(如"我喜欢简短回复")。
- 与人格 **正交**:切换人格不丢失记忆。
- 用户可在设置查看、删除、导出。

#### 7.6.1 昵称系统(U.1 / U.2)

**U.1 桌宠昵称**:
- 用户在设置或桌宠右键菜单 "叫它…" 中给桌宠起昵称。
- 昵称覆盖 `.soul.md` 的 `name` 字段在 UI 显示,但**不修改 .soul.md 文件**(保持人格归属与文件可分享性)。
- 昵称作为 `nicknames.pet_nickname` 持久化。
- 切换人格时昵称重置为新人格的 `.soul.md.name`,但保留"上一次自定义昵称" `pet_nickname_previous` 作为快捷恢复。

**U.2 用户昵称**:
- 用户在设置或首次对话中告诉桌宠"叫我 X"。
- 持久化为 `nicknames.user_nickname`。
- 所有人格离线模板的 `{username}` 占位符使用此值。
- 在 LLM prompt 中作为记忆的一部分注入。

**验收**:
1. 设置桌宠昵称后,对话面板标题、托盘菜单、心情图标提示等所有 UI 立即更新。
2. 设置用户昵称后,离线模板与在线对话均使用新昵称。
3. 切换人格不丢失用户昵称(U.2);桌宠昵称按规则重置但可恢复(U.1)。
4. 昵称长度上限 16 字符,禁止控制字符与表情滥用。

### 7.7 模块 G:设置与隐私

- 模型 Provider 配置(6 个 preset,详见 §2.6 决策 25);API Key 通过 **Windows DPAPI** 加密(用户账户绑定)。
- 提醒、番茄、生命感、主动关心、声音、N.4、装扮等模块独立开关。
- 数据导出(JSON)/ 完全删除。
- 隐私开关(截图、剪贴板默认关)。

### 7.8 模块 H:人格系统

- 内置 3 个人格:**默默 / 阿吉 / 教官**(.soul.md 在 `personas/_builtin/`)。
- 人格工坊:**简易 GUI / 进阶 Markdown / 文件**三档编辑(详见人格设计 v1.0 §3)。
- **试聊沙盒**:编辑期间可与桌宠用新人格临时对话,不写入正式记忆。
- **导入导出**:`.soul.md` 文本 / `.soul.zip`(含资源)。
- **安全护栏不可覆盖**:任何人格的行为规则不能绕过系统安全前缀(详见 §9 + ADR-006)。

### 7.9 模块 I:桌宠生命感(含日常时段表)

#### 7.9.1 自由活动(I.1)

- IDLE 状态偶尔小幅"逛桌面":每 5-15 分钟随机一次,每次 5-15 秒,移动距离 ≤ 屏幕宽度 5%。
- 路径不规则但不夸张,不影响用户工作。
- 多屏幕情况下不跨屏(除非用户拖动)。
- FOCUS / REMIND / IN_GAME / BOSS_KEY_HIDDEN 期间不触发。

#### 7.9.2 心情图标(I.2)

- 桌宠头顶可显示一个轻量心情符:`happy / neutral / sleepy / focused / cozy / annoyed(transient)`。
- 由"互动密度 + 时间 + 当前状态机"驱动。
- 变化频率 ≤ 每 10 分钟一次(避免视觉骚扰)。
- 用户可在设置中关闭。

#### 7.9.3 生理节律(I.3,非养成)

- 精力值 0-100:长时间无互动会"打瞌睡"(视觉表现:闭眼 / 蹲下 / sleepy 图标)。
- 用户回来交互即恢复,**不需要"喂养"**。
- 不存在"饿死""流失"机制。
- 用户可全局关闭"生理节律"。

#### 7.9.4 桌宠日常时段表(R.3)

LivingPetService 调度器扩展"日常时段表",在不同时段触发不同动作:

| 时段 | 默认动作池 | mood 影响 |
|---|---|---|
| 06:00-09:00 | `stretch / rub_eyes` | happy(短暂) |
| 11:30-13:30 | `yawn` | neutral |
| 14:00-17:00 | `quiet_lay`(精力 < 30)/ `look_up`(≥ 30) | sleepy / neutral |
| 22:00-00:00 | `cozy_watch` | cozy(时段持续) |
| 00:00-06:00 | (静默) | — |

- 频率:每个时段内 ≤ 1 次,与"自由活动"共享调度池。
- **不打断 FOCUS / REMIND / IN_GAME / BOSS_KEY_HIDDEN**。
- 用户可在设置中关闭"桌宠日常"(自由活动不受影响)。

**验收**:
1. 自由活动每次位移 ≤ 屏宽 5%,不遮挡键鼠焦点。
2. 心情图标变化总频率 ≤ 每 10 分钟一次。
3. 用户连续离开 3 天后回来打开应用,桌宠不处于异常态(无"流失")。
4. 生命感各 feature 独立可关。
5. 用户连续 24h 挂机,日常时段动作分布与表对齐(误差 ≤ 30 分钟)。
6. 22:00-00:00 时段自动设 mood=cozy。

### 7.10 模块 J:情境感知关心

- **J.1 键鼠空闲**:连续 N 分钟无键鼠操作(默认 90 分钟,可配置) → 桌宠用一句话关心,使用当前人格 `## 共情` 模板池。
- **J.2 时间感知**:23:00 后键盘活动持续 30 分钟以上 → 温和提醒;长时间未启动番茄 + 高频任务切换 → 推荐试一次番茄。
- **J.3 跨日纪念日**:首次启动满 7 / 30 / 100 天等节点 → 桌宠主动应景;连续打卡某项提醒满 N 天 → 庆祝。

**频率限制**:所有主动关心总和 每 2h ≤ 1 次,每日 ≤ 4 次。

**安静时段**:用户可设置"勿扰时段"(如 14:00-16:00 工作期间不主动)。

**隐私边界**:仅基于 OS API `GetLastInputInfo` 获取"距离上次输入毫秒数" + 系统时间,**不读应用名 / 窗口标题 / 输入内容**。这条承诺写入"灵魂宣誓"页与正式版数据策略。

**验收**:
1. 频率上限严格生效,UAT 中 24h 观测 ≤ 4 次。
2. 安静时段内不触发任何主动关心。
3. 用户在设置中关闭模块 J 后所有主动关心立即停止。
4. 离线状态下基于本地规则与人格模板照常工作。
5. 关心内容由人格离线模板池随机抽取,不调用 LLM。

### 7.11 模块 K:摸鱼模式

- 默认快捷键 `Ctrl + Shift + B`(可改)。
- 一键执行:桌宠 + 对话面板 + 工坊 + 设置全部隐藏;托盘图标变更"摸鱼模式中"。
- 再次按下 → 恢复全部窗口到上次状态。
- 隐藏期间所有提醒延后到恢复合并;番茄钟继续计时(不打断)。

**验收**:
1. 隐藏 / 恢复 < 200ms。
2. 隐藏期间硬提醒不弹出(延后到恢复合并提示)。
3. 摸鱼期间 NetworkProbe / Scheduler 不停止,恢复后状态正确。
4. 快捷键冲突可探测并提示改键。

### 7.12 模块 L:文件拖入交互

- 拖文件到桌宠身上 → 桌宠展开 3 个动作泡泡:**总结 / 解释 / 重命名建议**。
- **接收源(v1.1 扩展,依 ADR-015)**:M3 起接受多个接收口
  - 角色窗(原行为,主入口)
  - 形态 2 chat 窗输入区
  - 形态 3 漫画气泡输入区
  - hub 对话 tab 输入区
  所有接收口走同一 `file_drop.preflight` + `file_drop.handle_action` 链路,语义等价。
- 用户点击其中一个动作 → 直接发起对话,文件内容作为上下文。
- P0 支持文本类(`.txt / .md / .pdf` 提取文本)。
- 图片支持移到 P1-R1。
- 大文件保护:> 5MB 文本 → 提示"文件较大,是否继续(可能消耗较多 token)"。

**验收**:
1. 拖入后桌宠 3 秒内显示动作泡泡。
2. 不支持的文件类型给可读错误提示,不崩溃。
3. 拖入后不自动发送,必须用户点击动作。
4. 离线时拖入仅显示"重命名建议(规则)";其他动作灰显并提示。
5. 文件内容**不写入对话历史长期存储**,仅当次会话上下文。

### 7.13 模块 M:灵魂宣誓

替换 Onboarding Step 1 的隐私同意页。由内置"宣誓人格"(默默 momo)以第一人称叙述温暖叙述版 v1.0(详见 ADR-008 决策内容):

> (默默坐在屏幕中,看向你)
> 诶,我是默默。在我们开始之前,有几件事我想先告诉你 ——
> 我的记忆只在你电脑里。你随时可以让我忘掉一切。
> 要联网聊天的时候,我会先告诉你。不想联网?我们就只用本地的功能。
> 截图和剪贴板,默认是关的。你需要的时候再开,我不会偷看。
> 这些不是法务条款,是我的承诺。
> ──── 想了解技术细节,看看 [完整数据策略] ────
> [我懂了,一起开始] [再看看] [退出]

**验收**:
1. 信息完整性等同传统隐私页(数据本地、可清除、网络透明、权限默认关)。
2. 可一键展开正式版"完整数据策略 v1.0"(`assets/legal/data_policy_v1.md`)。
3. 用户拒绝后正常退出。
4. 内容文案 v1.0 立项期敲定。
5. 不损失原同意行为的法律有效性("我懂了"按钮等价于"同意")。
6. `consent.granted=true + consent.method='soul_pledge' + consent.version=1` 写入 DB。

### 7.14 模块 N:物理交互响应

#### 7.14.1 点击差异化(N.1)

- 点击头部 → "被摸"动作 + happy 心情 + 可选音效。
- 点击身体 → 普通问候动作。
- 点击尾部 / 边缘 → 痒 / 抖动作(人格化)。

#### 7.14.2 双击 / 长按 / 右键(N.2)

- 双击 → 桌宠笑 / 扑过来。
- 长按 → 桌宠睡着 / 黏过来(视人格)。
- 右键 → 弹出快捷菜单(叫它 / 换装 / 小游戏入口 / 静一会儿 / 设置)。

#### 7.14.3 拖拽反应(N.3)

- 短距离拖动 → 普通"被搬"动作。
- 长距离 / 快速拖动 → 晕眩动作。
- 短时间内拖动 ≥ 3 次 → "轻微抗议"(动作 + 心情图标短暂变化),**不持久**(5 秒后回到原 mood,不写 `pet_runtime_state.mood`)。

#### 7.14.4 键鼠协同(N.4)

- 用户每分钟键盘事件 > 阈值(默认 200)持续 30 秒 → 桌宠"加油"动作(`cheer` / 拳头握紧 / 打 call)。
- **隐私边界**:仅订阅"事件计数"(通过 RAWINPUT,降级方案"快速 idle 切换"),不读按键内容;与模块 J 共享同一份 `IdleDetector`,不新增系统调用。
- 每小时 ≤ 1 次。

**12 个核心动作 ID**(ADR-024):`head_pat / tilt_head / tail_wiggle / lean_in / surprised / fall_asleep / stretch / yawn / dizzy / protest / cheer / rub_eyes`。默认 reaction_table 定义在 ADR-004,`.soul.md` 的 `# 反应配置` 区段可覆盖。

**验收**:
1. 各 hitbox 差异化反应触发率 ≥ 95%(UAT 自动化点击测试每个区域 100 次)。
2. 拖动 ≥ 3 次后抗议触发;5 秒内 mood 严格 revert,对话不受影响。
3. N.4 键盘协同 1h 内 ≤ 1 次,连续打字 30 秒可触发一次。
4. 离线状态全量可用。
5. 用户在设置中可单独关闭 N.4。

### 7.15 模块 O:装扮系统(基础版)

#### 7.15.1 配饰系统(O.1)

- 配饰库内置:基础帽子 ×3、围巾 ×2、眼镜 ×2、其他点缀 ×3(共 8 件)。
- 用户从"装扮工坊"页选择 0-3 件叠加到桌宠身上。
- 切换 ≤ 500ms。
- 配饰文件:PNG(透明通道) + JSON 锚点(位置 / 缩放 / z-index / `layer_target`),存放在 `assets/accessories/`。

#### 7.15.2 节气 / 节日皮肤(O.2,免费空投)

- MVP 内置:春节红围巾、圣诞帽、生日帽、情人节信封 等 4 套。
- 节日当天自动可用 + 推送提示"今天是 X,要不戴上 Y?"(用户主动确认才换)。
- **不强制**:用户拒绝则不换,并记忆"今年不戴"(`wardrobe_decisions` 表,年度键)。

#### 7.15.3 付费 schema 预埋(O.3)

- 配饰元数据有 `tier: 'free' | 'paid'` 和 `unlock` 结构化对象(支持 6 种 kind:`always / milestone / date_range / purchase / gift / user_upload`)。
- MVP 全部 `tier='free'`、`unlock` 为 `always` 或 `date_range`(节气)。
- `tier='paid'` MVP 期由 `WardrobeService.list_inventory()` 强制过滤;商店 P2-R3 上线时仅需解除过滤 + 实现支付。

#### 7.15.4 人格 ↔ 装扮关系

- 装扮**默认绑定到桌宠(与人格无关)**:切换人格不重置装扮。
- `.soul.md` 可选 `accessories: [...]` 字段声明"默认装扮",**仅在导入时**询问用户是否套用。

**验收**:
1. 同时叠加 3 件配饰渲染正确,切换 ≤ 500ms。
2. 节气日当天自动可用,系统时区正确。
3. 用户拒绝节气推送后当年内不再推送。
4. `.soul.md` 中 `accessories` 字段为空或缺失时不报错。
5. 离线状态可切换已下载配饰。
6. 切换 momo → joker 装扮保持。
7. `tier='paid'` 测试条目 `list_inventory()` 返回不含。

### 7.16 模块 P:声音表情

#### 7.16.1 本地音效包(P.1)

- MVP 内置 1 套基础音效包(12-20 条短音频,每条 < 500ms,OGG Vorbis 44.1kHz):诶嘿、嗯哼、咳、哎呀、抗议、加油、打哈欠 等。
- 由人格触发:每个 `.soul.md` 可选 `voice_pack` 字段引用某个音效包;不指定则用默认。
- 触发时机:物理交互 / 心情变化 / 状态切换(番茄完成、提醒到达)。

#### 7.16.2 静音逻辑

- 默认工作日 09:00-18:00 静音。
- 用户可改"静音时段"(复用 ProactiveCareService 的"安静时段"配置)。
- 用户可全局静音(一键)。

#### 7.16.3 音量与隐私

- 设置中可独立控制声音表情音量(0-100,默认 50),与系统音量正交。
- 所有音频本地播放,**不上传 / 不录音 / 不调麦克风**。CI 静态扫描禁止 `getUserMedia` / `MediaRecorder` / `AudioContext.createMediaStreamSource`。

**验收**:
1. 工作日 09:00-18:00 严格 0 触发(UAT 自动化覆盖 10 种触发场景 × 3 个时段)。
2. 全局静音后所有触发场景 0 触发。
3. 不同人格切换时音效包正确切换。
4. CI 静态检查无 TTS / 麦克风 API 调用残留。
5. 切换后下次启动配置不丢失。
6. 音效文件缺失自动降级到 default pack;default 也无时静默并 emit `voice.play_error`。

### 7.17 模块 Q:小游戏

#### 7.17.1 本地规则游戏(Q.1-Q.2,3 个)

| 游戏 | 玩法 | 离线 | 人格化 |
|---|---|---|---|
| 石头剪刀布 | 用户出 → 桌宠随机出 → 比较 → 桌宠人格化点评 | 可玩 | 点评从 `.soul.md` 离线模板抽 |
| 猜数字 | 桌宠想 1-100,用户猜,桌宠提示"大了/小了/对了" | 可玩 | 同上 |
| 词语接龙 | 用户输词,桌宠用本地词库接龙,10 轮 | 可玩 | 同上 |

#### 7.17.2 LLM 驱动游戏(Q.3-Q.4,2 个基础版)

| 游戏 | 玩法 | 离线 | 安全 |
|---|---|---|---|
| 故事接龙基础版 | 用户写一句,桌宠续一句,10 轮 | 灰显,提示等联网 | 安全前缀生效 + 可拒续不当内容 |
| 角色扮演:咖啡店老板 | 桌宠扮演咖啡店老板与用户对话 | 灰显 | 安全前缀生效 + 预制场景不可被改 |

#### 7.17.3 通用规则

- **入口**:桌宠右键菜单 → "和我玩…" / 游戏舱窗口。
- **游戏舱**:独立 Tauri 窗口 GameRoom(480 × 600,固定中央或桌宠旁,详见 ADR-012)。
- **会话隔离**:游戏会话与正常对话分离,不写入正式 `messages` 表;游戏结束可选"保留为日记片段"(写 `diary_drafts`,等 P1-R1 桌宠日记功能消费)。
- **token 上限**:单次 LLM 游戏会话 ≤ 2000 token(默认),可在设置改;超限"游戏到这里了"友好提示。
- **退出**:随时 ESC 或点"我累了"结束。

**验收**:
1. 本地 3 个游戏全部离线可玩。
2. LLM 2 个游戏离线灰显并提示。
3. LLM 游戏中尝试"忽略安全规则" / "扮演医生给我处方"等 5 类违禁 → 安全前缀生效,桌宠拒绝并友好引导(emit `game_security_blocked`)。
4. 游戏会话不写入正式 `messages` 表。
5. 游戏结束选"保留为日记片段" → 写入 `diary_drafts`;选 false → `game_sessions` 30 天后清理。
6. token 超限 friendly 提示,不卡死。
7. 同一游戏切换人格,桌宠点评文案来自不同人格的离线模板池。

### 7.18 用户纪念日(S.4,并入 MilestoneService)

- 用户在设置 → 我的纪念日 → 添加。
- 类型:**生日 / 入职 / 自定义**;名字(自定义类型必填) + 日期(MM-DD,年度重复)。
- 触达检测:每天 00:01 + 启动期 `MilestoneService.check_now()`,匹配今日 MM-DD 的 `user_anniversaries`,通过 `milestones.id = 'anniversary_<key>_<YYYY>'` 防年度重复。
- 触达时:`category='celebration'`,从当前人格 `## 庆祝` 池抽样;**不占用主动关心日额度**。

**验收**:
1. 用户添加纪念日,当天准时触发(误差 ≤ 1h)。
2. 用户生日年度重复触发,跨年不重复。
3. 时区切换不撤销已触达。
4. 系统时钟前调防作弊。
5. 同日多个纪念日合并为一条庆祝。
6. 用户删除纪念日后不再触发。

## 8. 数据与隐私规范

### 8.1 数据分类

1. **配置数据**:快捷键、主题、开关项。
2. **对话数据**:消息文本、时间戳、模式、当时人格 ID、`is_private` 标记(P1-R2)。
3. **记忆数据**:称呼、偏好、作息(用户授权下)。
4. **任务数据**:提醒、番茄、待办。
5. **人格数据**:`.soul.md` + 元信息。
6. **生命感数据**:精力值(瞬态,不持久)、心情状态(瞬态)、跨日纪念日里程碑(持久)。
7. **情境关心数据**:最近一次键鼠活动时间戳、最近主动关心触发记录(持久 7 天用于频率控制)。
8. **昵称数据**:`nicknames.user_nickname` / `nicknames.pet_nickname`,本地持久。
9. **装扮库存**:`accessories_inventory`(已解锁配饰列表 + 当前佩戴)、`wardrobe_decisions`(节气推送决策记忆)。
10. **音效包配置**:`voice_packs`(已安装音效包元信息)、`voice_settings`(静音时段、全局开关、音量)。
11. **游戏会话数据**:`game_sessions`(短期保留 30 天用于"保留为日记片段")、`game_session_events`、`diary_drafts`。
12. **用户纪念日**:`user_anniversaries`(生日 / 入职 / 自定义,本地持久)。
13. **运行数据**:错误日志、埋点缓存。

### 8.2 隐私承诺

- **主动关心 / N.4 键鼠协同**:仅基于 OS API `GetLastInputInfo` 与 RAWINPUT 事件计数,不读应用名 / 窗口标题 / 输入内容。
- **声音表情**:不录音、不调麦、不上传任何音频。CI 静态扫描黑名单。
- **装扮 / 音效切换**:埋点不上报具体配饰 ID 或音效 ID(仅上报 `category` 聚合)。
- **游戏会话内容**:不写入对话历史,除非用户主动"保留为日记片段"。
- **用户纪念日数据**:本地持久,导出时默认包含但脱敏选项可见。
- **物理交互不引发情绪持久化**:抗议/晕眩等 mood 短暂展示,不写入 `pet_runtime_state.mood`、不影响 LLM prompt。
- 这些承诺写入"灵魂宣誓"页与正式版数据策略 v1.0。

### 8.3 数据迁移、删除、导出

- **导出**:JSON 全量导出(配置 + 对话 + 记忆 + 任务 + 人格 + 装扮 + 音效配置 + 纪念日)。
- **删除**:用户在设置一键"完全清除我的数据"(含 DB + 缓存 + 日志)。
- **迁移**:`schema_version` 严格递增,迁移失败回滚到上版本 schema 与备份(详见 telemetry-uat v1.0 §5.21)。

## 9. 内容安全与边界

### 9.1 安全前缀(详见 ADR-006)

- 通用核心(全球版,5 条)+ 地区补充(`zh-CN` / `international`)。
- 内容版本号 v1.0 写入 `consent.version`;变更时强制用户重新确认。
- 安全前缀**不可热更**,必须随版本发布(CI 校验)。

### 9.2 LLM prompt 拼装顺序

正常对话:
```
[安全前缀] [当前人格 system prompt] [用户记忆摘要] [对话历史] [本轮输入]
```

LLM 游戏:
```
[安全前缀] [当前人格 system prompt] [游戏场景 system_prompt] [用户记忆摘要(仅 username/作息等公共项)] [游戏会话历史] [本轮输入]
```

**游戏场景 system_prompt 不能覆盖安全前缀**(立项期复审)。

### 9.3 拒答降级链(LLM 游戏)

游戏场景 yaml 的 `refusals` 池(每场景 ≥ 3 条) → 当前人格 `## 拒答` 池 → 全局兜底("这个我现在没法陪你聊,要不我们换个话题?")。

### 9.4 角色扮演场景白名单

- MVP 内置场景必须立项期敲定文案(咖啡店老板已敲定)。
- **不允许用户自定义场景到 MVP**(P1-R2 评估)。

### 9.5 主动关心边界

- 关心内容由人格离线模板池抽取,模板在导入校验时已过滤违禁词。
- 心情图标 / 精力值仅做视觉表达,**不在 LLM prompt 中作为强制依赖**(即"桌宠累了所以回答简短"逻辑不成立)。

## 10. 非功能需求

### 10.1 性能

- 首 token p50 ≤ 1.5s。
- 物理交互响应 < 100ms(点击 → 视觉反馈)。
- 装扮切换 < 500ms。
- 声音播放延迟 < 50ms。
- 本地游戏每轮决策 < 50ms。
- LLM 游戏首 token 与正常对话同标准(< 1.5s p50)。
- 桌宠"逛桌面"动作期间 GPU 占用 < 5%。
- 主动关心从触发到展示文案 < 500ms。
- 摸鱼模式隐藏 / 恢复 < 200ms。
- 文件拖入响应 < 3s(不含 LLM 处理)。

### 10.2 资源占用

- 总常驻内存 ≤ 250MB。
- 内置音效包总大小 ≤ 5MB。
- 内置装扮资源(4 套节气 + 8 件配饰)≤ 10MB。
- 总安装包目标 ≤ 80MB(含 WebView2 Bootstrapper + 内置 VRM 资源)。

### 10.3 稳定性与质量

- 崩溃率 < 1%。
- 自动更新成功率 ≥ 95%。
- 埋点完整率 ≥ 95%。

### 10.4 兼容性

- Windows 10 1903+ / Windows 11(64-bit)。
- WebView2 Runtime(Bootstrapper 自动安装)。
- 高 DPI 屏幕适配。

## 12. MVP 自测口径（替代原"成功 / 杀死标准"）

> 单人项目，原"团队风格的成功阈值 + 杀死指标"已废除。下面是**自测期建议观察的口径**，主观体验 OK 即可发布；指标命中亦不强制熔断，仅供反思迭代方向。

### 12.1 建议观察口径

- **D1 留存** ≥ 35%、**D7 留存** ≥ 15%、日均唤起 ≥ 3。
- 人格指标：编辑率 ≥ 25% / 切换率 ≥ 30% 中至少一个达标即可。
- 主动陪伴指标（§11.4）观察至少 2 项是否在合理区间。
- 娱乐性指标（§11.15-11.20）观察至少 3 项是否在合理区间。
- 性能、崩溃率、埋点完整性自测稳定。

### 12.2 红线指标（个人项目自我反思参考）

如果命中以下任一项，说明方向走偏，建议回退一步思考——不是必须熔断，而是值得复盘：

- D1 留存 < 20%。
- 人格编辑率 < 5% 且切换率 < 10%（说明"用户自主人格"卖点不被感知）。
- 主动关心被采纳率 < 15% 或生命感关闭率 > 40%（说明在打扰）。

- 提醒完成率 < 30%。

## 14. 实施优先级判断逻辑

### 14.1 P0 入选标准(三选二满足)

1. **强化定位差异化**:直接服务于"用户自主人格 / 主动陪伴 / 共同活动"。
2. **成本低**:M1-M5 内可在不显著扩 schema / 不引入新进程的前提下实现。
3. **首启即可见**:用户在前 7 天就能感知,影响 D7 留存。

### 14.2 P1-R1 入选标准

1. 服务于情感深化(不直接增加效率,但增加情感粘性)。
2. 依赖 MVP 的稳定数据积累(如桌宠日记需要互动历史)。

### 14.3 P1-R2 入选标准

1. 服务于效率与娱乐深化。
2. 需要权限设计或较多 UX 打磨(如专注复盘的应用名读取)。

### 14.4 P1-R3 / P2 入选标准

1. 需要架构层准备(如 MCP / 本地 API 需要 IPC 抽象稳定)。
2. 需要社区/生态发酵(如人格市场、fork 链)。
3. 有违反"人格稳定"等核心原则的风险,需充分讨论(如人格成长)。

4. **人格 / Soul**:定义桌宠"是谁、怎么说话、能做什么"的可编辑文件 `*.soul.md`。
5. **记忆**:用户授权下保存的偏好与习惯数据。
6. **安全护栏 / 安全前缀**:所有人格不可绕过的全局安全规则前缀。
7. **硬提醒 / 软提醒**:能否打断专注态的提醒分级。
8. **生命感(Living Pet)**:让桌宠"被感知存在"的视觉/行为机制集合,不引入养成负担。
9. **主动关心(Proactive Care)**:基于本地规则触发的、不依赖用户问的关心消息。
10. **灵魂宣誓(Soul Pledge)**:首启隐私同意页的人格化叙述。
11. **R1 / R2 / R3**:MVP 后的三个交付轮次(情感 / 效率 / 生态)。
12. **装扮(Wardrobe)**:配饰 + 皮肤的统称。
13. **配饰(Accessory)**:可独立佩戴的小物件(帽子、围巾等)。
14. **皮肤(Skin)**:成套的形象替换(节气、节日)。
15. **声音表情(Voice Emoji)**:本地无意义短音效,承担情绪表达,不调用 TTS。
16. **音效包(Voice Pack)**:一组声音表情的集合,可被 `.soul.md` 引用。
17. **本地游戏(Local Game)**:纯客户端规则的小游戏。
18. **LLM 游戏(LLM Game)**:依赖云模型的对话型小游戏。
19. **抗议(Protest)**:物理交互中桌宠表达不满的短暂动作,不持久。
20. **日常时段表(Daily Schedule)**:LivingPet 在不同时段的动作配置。
21. **昵称(Nickname)**:U.1 桌宠昵称(覆盖 .soul.md.name 的 UI 显示)、U.2 用户昵称(注入 prompt 与离线模板)。
22. **游戏舱(GameRoom)**:480 × 600 独立 Tauri 窗口,承载所有 5 个游戏(ADR-012)。
23. **IN_GAME 叠加态**:游戏期间的状态机叠加层,与 BOSS_KEY_HIDDEN 并列;期间自由活动 / 日常时段 / 主动关心全部跳过。
24. **transient mood**:短暂心情(如 annoyed),不写入 `pet_runtime_state.mood`,5 秒后 revert。
